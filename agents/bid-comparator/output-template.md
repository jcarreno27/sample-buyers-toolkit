# Bid Comparator — output template

What a Bid Comparator response should look like. Two absolutes: gaps in a
bid appear as **NOT STATED** (never filled with typical values), and the
output frames the decision without making it.

```
BID COMPARISON — [project name]
Spec recap: [one line]
Bids compared: [count] | Specs identical across bidders: [yes/no/unknown]

COMPARISON TABLE
| Term | Supplier A | Supplier B | Supplier C |
|---|---|---|---|
| CPI (currency) | | | |
| Total at full n | | | |
| Minimum / other fees | | | |
| IR assumed | | | |
| LOI assumed | | | |
| If actual IR is lower | | | |
| Feasible n committed | | | |
| Timeline committed | | | |
| Soft launch | | | |
| Sources / blend | | | |
| Quota approach | | | |
| Quality measures | | | |
| Who pays for removals | | | |
| Caveats volunteered | | | |

ARE THESE PRICES COMPARABLE?
[Plain English: which assumptions differ, what bet each bid is making,
where adjustment clauses create exposure. No "adjusted price" math.]

RISK READ, PER BID
Supplier A — [Low/Medium/High]: [reasons — "per their response" for
  stated facts, "inference" clearly labeled for pattern reads]
Supplier B — ...
Supplier C — ...

DECISION FRAMING (you decide, not me)
- Choose A if: [what you'd be optimizing for]
- Choose B if: ...
- Choose C if: ...

BEFORE YOU AWARD, ASK:
Supplier A: 1. [sharpest question first — usually their NOT STATED cells]
Supplier B: 1. ...
Supplier C: 1. ...
```
